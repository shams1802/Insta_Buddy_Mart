# Backend Services - Issues & Fixes

## Summary

This document identifies known issues in IAM Service and Order Service, with reproducible test cases and fixes.

## IAM Service Issues

### Issue #1: OTP Validation Accepts Any 6-Digit Code

**Severity:** ⚠️ Medium (Security)

**Description:**
The OTP verification endpoint accepts ANY 6-digit code, not just the one generated by the system.

**Location:** `backend/IAM_Service/src/services/authService.js`, line ~180

**Current Code:**
```javascript
async function verifyOtp(email, code) {
  // Find user
  const userResult = await db.query(
    `SELECT id, full_name, email, phone, role, kyc_verified, is_active
     FROM users_iam WHERE email = $1`,
    [email]
  );

  if (userResult.rows.length === 0) {
    const error = new Error('No account found with this email');
    error.statusCode = 404;
    error.code = 'USER_NOT_FOUND';
    throw error;
  }

  const user = userResult.rows[0];

  // Find the most recent valid (unexpired, unverified) OTP for this user
  const otpResult = await db.query(
    `SELECT id, code, expires_at FROM otp_codes
     WHERE user_id = $1 AND verified = false AND expires_at > NOW()
     ORDER BY created_at DESC LIMIT 1`,
    [user.id]
  );

  if (otpResult.rows.length === 0) {
    const error = new Error('No valid OTP found. Request a new one.');
    error.statusCode = 400;
    error.code = 'NO_VALID_OTP';
    throw error;
  }

  const storedOtp = otpResult.rows[0];

  // ❌ BUG: This doesn't check if the code matches!
  // It just marks ANY code as verified
  if (true) {  // Should be: if (code === storedOtp.code)
    await db.query(
      'UPDATE otp_codes SET verified = true WHERE id = $1',
      [storedOtp.id]
    );

    // Generate tokens
    const accessToken = generateAccessToken(user);
    const refreshToken = generateRefreshToken(user);

    return {
      user,
      accessToken,
      refreshToken,
    };
  }
}
```

**Test Case:**
```javascript
// Should FAIL but doesn't:
POST /api/v1/auth/otp/verify
{
  "email": "user@example.com",
  "code": "999999"  // Wrong code, but still accepted
}
```

**Fix:**
```javascript
async function verifyOtp(email, code) {
  // ... user lookup code ...

  const storedOtp = otpResult.rows[0];

  // ✓ FIX: Actually compare the codes
  if (code !== storedOtp.code) {
    const error = new Error('Invalid OTP code');
    error.statusCode = 400;
    error.code = 'INVALID_OTP';
    throw error;
  }

  // Mark as verified and return tokens
  await db.query(
    'UPDATE otp_codes SET verified = true WHERE id = $1',
    [storedOtp.id]
  );

  const accessToken = generateAccessToken(user);
  const refreshToken = generateRefreshToken(user);

  return { user, accessToken, refreshToken };
}
```

### Issue #2: Missing Request Validation Middleware

**Severity:** ⚠️ Medium (API Design)

**Description:**
Some endpoints don't validate request payloads properly, allowing malformed requests to crash the server.

**Location:** `backend/IAM_Service/src/routes/auth.js`

**Current Implementation:**
```javascript
// ❌ Missing validation on some routes
router.post('/update-password', auth, async (req, res, next) => {
  // No schema validation - could crash if fields missing
  const user = await authService.updatePassword(
    req.user.id,
    req.body.currentPassword,  // Could be undefined
    req.body.newPassword,      // Could be undefined
    req.body.confirmPassword   // Could be undefined
  );
  // ...
});
```

**Fix:**
```javascript
// ✓ Add validation middleware
const updatePasswordSchema = Joi.object({
  currentPassword: Joi.string().required(),
  newPassword: Joi.string().min(6).required(),
  confirmPassword: Joi.string().required().valid(Joi.ref('newPassword')),
});

router.post('/update-password', 
  auth, 
  validate(updatePasswordSchema),  // Add validation
  async (req, res, next) => {
    // Now all fields are guaranteed to exist and be valid
    const user = await authService.updatePassword(
      req.user.id,
      req.body.currentPassword,
      req.body.newPassword,
      req.body.confirmPassword
    );
    // ...
  }
);
```

### Issue #3: Race Condition in User Registration

**Severity:** 🔴 High (Database Integrity)

**Description:**
Two simultaneous registration requests with the same email can both succeed if they check for duplicates at the same time.

**Location:** `backend/IAM_Service/src/services/authService.js`, line ~20

**Current Code (Vulnerable):**
```javascript
async function registerUser({ fullName, email, phone, password, role }) {
  // Step 1: Check if user exists
  const existingUser = await db.query(
    'SELECT id FROM users_iam WHERE email = $1 OR phone = $2',
    [email, phone]
  );

  // 🔴 RACE CONDITION: Between here...
  if (existingUser.rows.length > 0) {
    throw new Error('Duplicate user');
  }

  // Step 2: Insert new user
  // ... and here, another request could insert the same email
  const result = await db.query(
    'INSERT INTO users_iam (full_name, email, phone, password_hash, role) VALUES (...)',
    [fullName, email, phone, passwordHash, role]
  );
}
```

**Fix (Atomic Operation):**
```javascript
async function registerUser({ fullName, email, phone, password, role }) {
  const client = await db.getClient();
  
  try {
    await client.query('BEGIN');  // Start transaction
    
    // Check for existing user (locked during transaction)
    const existingUser = await client.query(
      'SELECT id FROM users_iam WHERE email = $1 OR phone = $2 FOR UPDATE',
      [email, phone]
    );

    if (existingUser.rows.length > 0) {
      throw new Error('Duplicate user');
    }

    // Insert happens atomically within transaction
    const passwordHash = await bcrypt.hash(password, SALT_ROUNDS);
    const result = await client.query(
      `INSERT INTO users_iam (full_name, email, phone, password_hash, role)
       VALUES ($1, $2, $3, $4, $5)
       RETURNING id, full_name, email, phone, role, kyc_verified, is_active, created_at`,
      [fullName, email, phone, passwordHash, role || 'requester']
    );

    await client.query('COMMIT');
    return result.rows[0];
  } catch (error) {
    await client.query('ROLLBACK');
    throw error;
  } finally {
    client.release();
  }
}
```

## Order Service Issues

### Issue #4: Missing Input Validation on Order Items

**Severity:** ⚠️ Medium

**Description:**
Order items array can be empty or have invalid quantities, causing database errors.

**Location:** `backend/Order_Service/src/routes/orders.js`

**Current Code:**
```javascript
const createOrderSchema = Joi.object({
  storeName: Joi.string().required(),
  deliveryAddress: Joi.string().required(),
  requesterLat: Joi.number().required(),
  requesterLng: Joi.number().required(),
  storeLat: Joi.number().required(),
  storeLng: Joi.number().required(),
  estimatedCost: Joi.number().min(0).required(),
  items: Joi.array().items(
    Joi.object({
      itemName: Joi.string().required(),
      quantity: Joi.number().min(0).required(),  // ❌ Allows 0 quantity
      estimatedPrice: Joi.number().min(0).required(),
    })
  ), // ❌ Doesn't require at least 1 item
  notes: Joi.string().optional(),
});
```

**Fix:**
```javascript
const createOrderSchema = Joi.object({
  storeName: Joi.string().required(),
  deliveryAddress: Joi.string().required(),
  requesterLat: Joi.number().required(),
  requesterLng: Joi.number().required(),
  storeLat: Joi.number().required(),
  storeLng: Joi.number().required(),
  estimatedCost: Joi.number().min(0).required(),
  items: Joi.array()
    .min(1)  // ✓ Require at least 1 item
    .items(
      Joi.object({
        itemName: Joi.string().required(),
        quantity: Joi.number().min(1).required(),  // ✓ Require quantity >= 1
        estimatedPrice: Joi.number().min(0).required(),
      })
    )
    .required(),
  notes: Joi.string().optional(),
});
```

### Issue #5: Delivery Fee Calculation Doesn't Match Documentation

**Severity:** 🟡 Low (Data Consistency)

**Description:**
The delivery fee formula doesn't match the documented ₹30 minimum and distance-based calculation.

**Location:** `backend/Order_Service/src/services/orderService.js`

**Test Case:**
```javascript
// Should be ₹30 minimum for distances < 3km
// Should be ₹30 + (distance_km * 5) for distances >= 3km

// Current code might calculate differently
```

**Fix Needed:**
```javascript
async function calculateDeliveryFee(storeLocation, requesterLocation) {
  const distance = calculateDistance(storeLocation, requesterLocation);  // in km
  
  // ✓ Correct formula
  if (distance < 3) {
    return 30;  // Minimum ₹30 for distances < 3km
  } else {
    return 30 + (distance * 5);  // ₹30 base + ₹5 per km
  }
}
```
